STAGE 1 — PROVISION THE KV STORE  *** MOST IMPORTANT SINGLE STEP ***
Without this the site still runs, but you LOSE: date holds, webhook amount
verification, durable rate limiting, 12-month PII auto-purge, and the token
vault (PII stays out of URLs only with the store). Do not go live without it.
------------------------------------------------------------------------
[ ] 1.1  On Vercel: Storage > add a Redis/KV store (Upstash) to the project.
         This auto-injects KV_REST_API_URL and KV_REST_API_TOKEN.
         (Elsewhere: create an Upstash Redis DB and copy its REST URL + token
          into UPSTASH_REDIS_REST_URL / UPSTASH_REDIS_REST_TOKEN.)
[ ] 1.2  Confirm both variables are present in the deployment environment.

STAGE 5 — PAYMENTS: VIVA DEMO (get the full flow working before real money)
------------------------------------------------------------------------
[ ] 5.1  In the Viva DEMO portal, get Smart Checkout credentials:
           VIVA_CLIENT_ID, VIVA_CLIENT_SECRET   (Settings > API Access)
[ ] 5.2  Create/note a payment SOURCE and its numeric code:
           VIVA_SOURCE_CODE   (Sales > Websites/Apps)
[ ] 5.3  On that source, set redirect URLs:
           Success -> https://YOURDOMAIN/booking/success
           Failure -> https://YOURDOMAIN/booking/failure
[ ] 5.4  Set  VIVA_ENV = demo  and  VIVA_WEBHOOK_VERIFICATION_KEY = (from Viva).
[ ] 5.5  Add a webhook in Viva pointing to
           https://YOURDOMAIN/api/viva/webhook
         Event type: "Transaction Payment Created" (id 1796). Save; Viva does a
         one-time GET verification (needs VIVA_WEBHOOK_VERIFICATION_KEY set).
[ ] 5.6  DEPOSIT (pre-auth) capture — needed to release/capture the damage hold
         FROM the site (otherwise you resolve holds in the Viva portal):
           VIVA_MERCHANT_ID, VIVA_API_KEY  (Payment API Basic-auth credentials)
         and in Viva enable: Settings > API Access >
           "Allow recurring payments and pre-auth captures via API".
         Deposit amount lives in content/siteConfig.ts (deposit.amountEur).

STAGE 6 — DEPLOY + END-TO-END TEST (on DEMO)
Viva webhooks and redirects cannot reach localhost, so this must be on the
deployed HTTPS URL.
------------------------------------------------------------------------
[ ] 6.1  Deploy to Vercel; point your domain at it (HTTPS auto).
[ ] 6.2  Open the site; confirm it loads, EL/EN toggle works, calendar shows
         availability, and the map/analytics render (if configured).
[ ] 6.3  Submit a booking request (tick the consent box). Confirm:
           - you (owner) get the request email WITH an "Approve" button;
           - the guest gets an acknowledgement email.
[ ] 6.4  Click Approve > Confirm. Confirm the guest gets a Viva pay link.
[ ] 6.5  Pay with a Viva DEMO test card. Confirm:
           - you land on /booking/success;
           - owner gets "PAID" email (with a "Send deposit hold link" button);
           - guest gets a receipt;
           - those dates now show as blocked on the site calendar.
[ ] 6.6  Deposit: click "Send deposit hold link", authorize the hold as the
         guest, then use the "Release / Capture" email link to RELEASE it.
         Confirm the guest gets the release email.
[ ] 6.7  Abuse checks: submit the request form ~6 times fast -> you should get
         a "too many requests" message (rate limiting works).
