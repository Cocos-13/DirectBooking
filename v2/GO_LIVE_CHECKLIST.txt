ROOT CAUSE CONFIRMED (2026-07-24, from the owner) — source 1015 was set to:
    Domain Name  cocosapartments.com   (BARE — 308-redirects to www)
    Success URL  https://cocosapartments.com/booking/success

cannot themselves error (no order lookup, no query-param dependency), which is how
we know the fault is 100% the URL config. FIX: move Domain Name AND both URLs to
the www host together (a URL/Domain mismatch is rejected by Viva), and spell the
failure path "failure". Then re-test.

CODE FIX (2026-07-23) — found while working Stage 5, blocked 5.6 AND 6.6:
lib/viva.ts sent the pre-auth CAPTURE and RELEASE calls to HOSTS.api
(demo-api.vivapayments.com / api.vivapayments.com). Those two calls belong to
Viva's LEGACY Payment API, which is served from a different host —
demo.vivapayments.com / www.vivapayments.com. Verified by probe:
  POST/DELETE /api/transactions/{id}  ->  401 on demo.vivapayments.com
                                          (route exists, auth rejected)
                                     ->  404 on demo-api.vivapayments.com
                                          (route does not exist)
So EVERY "Release" or "Capture" click would have failed with a 404 and shown
the owner "Viva rejected the request". Fixed: HOSTS.payments now serves those
two calls, and the capture body carries the documented amount + currencyCode +
customerTrns. This is the same host trap already noted in 5.4 for
/api/messages/config/token — same legacy API, same host.

CHECKED, NOT A BUG (2026-07-23): the webhook only accepts statusId "F"
(app/api/viva/webhook/route.ts:81), which looked wrong for a pre-auth. Viva's
status table confirms it is right: a successful pre-auth IS "F" (completed
successfully) and is told apart by transactionTypeId 1 (Card pre-auth); "C"
only appears LATER, on the original pre-auth once it has been captured, with
the capture itself landing as a separate "F" transaction. Our code doesn't rely
on transactionTypeId at all — it routes deposits by the "DEP|" merchantTrns
marker — so the deposit webhook path is sound. Don't "fix" this in 6.6.
